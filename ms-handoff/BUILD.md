# Roundcube "fluent2" skin — implementation brief

> **Read this first.** This is the original build brief, published unedited as the design
> rationale behind the skin. Every `§` reference in the source comments points here, so it is
> worth having open while reading the code. Two things differ from the repository you are
> looking at:
>
> - **The skin is named `businessclass`, not `fluent2`.** It was renamed after this brief was
>   written. Read `skins/fluent2/` and `plugins/fluent2_*` below as `skins/businessclass/` and
>   `plugins/businessclass_*`.
> - **`Roundcube Fluent 2 Theme.dc.html` is not in this repository.** It is a capture of
>   Microsoft's Fluent 2 design surface, and redistributing it under this repository's license
>   is not ours to do (see LICENSE). The skin it produced is original work and is all here; the
>   design source stays internal. Where the brief says "see the design file", the answer is now
>   in `styles/_tokens.scss` and the built `styles.css`.
>
> §12 tracks build progress against the plan. `docs/STATUS.md` records where that actually
> stands, and `docs/DECISIONS.md` records every point where the brief and reality had to be
> reconciled.

Build a from-scratch Roundcube skin named **fluent2** that renders the visual design in
`Roundcube Fluent 2 Theme.dc.html` (open that file in a browser for pixel reference — it is the
source of truth for layout, states and copy).

- Target: **Roundcube 1.6.x** as shipped by cPanel on shared hosting (PHP 7.4+/8.x, no root).
- Design language: **Microsoft Fluent 2** (fluent2.microsoft.design) — tokens, type ramp, elevation,
  motion, focus treatment.
- This is an **original mail UI in the Fluent 2 language**, not a clone of Microsoft's product UI.
  Do not copy Outlook's proprietary iconography, illustrations, marks or exact chrome.
- Chosen direction: **1a — three-column with pinned reading pane** (see §3.1). Directions 1b/1c in
  the design file are alternates; 1b's single-pane behaviour IS the mobile/narrow layout, and 1c's
  single-line rows ARE the "compact" density. Build all three as *modes of one skin*, not 3 skins.

Everything below is the contract. When the design file and this brief disagree, ask; do not guess.

---

## 1. Constraints that must hold

1. **No core patching.** Only files under `skins/fluent2/` plus optional small plugins in
   `plugins/fluent2_*`. Never edit `program/` or plugin sources — override their templates/CSS
   from the skin instead.
2. **Standalone skin**: `meta.json` has `"extends": null`. Do not inherit Elastic. But keep
   Elastic's element ids and layout hooks (`#layout`, `#layout-menu`, `#layout-sidebar`,
   `#layout-list`, `#layout-content`, `#taskmenu`, `.floating-action-buttons`) so third-party
   plugins that target them still work.
3. **Roundcube owns most markup.** The message list is generated by `rcube_list_widget`
   (`<table id="messagelist"><tr class="message unread flagged">…`). Style the classes it emits.
   Do not replace the list with custom DOM; add wrapper elements and CSS only.
4. **Progressive enhancement.** Every skin JS feature (density toggle, Focused/Other, hover quick
   actions, pane resize) must degrade to a working plain list if JS fails.
5. **Responsive parity with Elastic**: usable 360px → 2560px, touch targets ≥ 44px below 768px.
6. **Plugins styled**: `managesieve`, `zipdownload`, `archive`, `markasjunk`, `password`,
   `newmail_notifier`, `calendar` (or `libcalendaring`-based alternative), `enigma` if present.
7. **Tokens only.** No literal colors/sizes outside `styles/_tokens.scss` (provided — copy it in
   as-is). Review will grep for hex codes.
8. **Accessibility is a gate**, not a polish pass — see §9.

```
    _search.scss                # search bar, tokens, refine panel (§4.3)
    _plugins.scss               # zipdownload, markasjunk, password, enigma, notifier
    _responsive.scss            # breakpoints (§6) — LAST import so it wins
    _print.scss
    styles.scss                 # @use manifest, compiles to styles.css

    icons/fluent-sprite.svg     # Fluent UI System Icons subset (§10)

    includes/{header,menu,links,footer}.html
    login.html
    mail.html  message.html  messagepreview.html  compose.html  folders.html  ...
    settings/*.html   addressbook/*.html   plugins/*.html
```

`meta.json`:

```json
{
  "name": "Fluent 2",
  "author": "…",
  "license": "GPL-3.0",
  "extends": null,
  "config": {
    "message_list_layout": "widescreen",
    "supported_layouts": ["widescreen", "desktop", "list"],
    "dark_mode_support": true
  }
}
```

`branding.json` — the only file a customer edits:

```json
{
  "product_name": "Webmail",
  "logo": { "header": "images/logo-header.svg", "login": "images/logo-login.svg", "favicon": "images/favicon.png" },
  "accent": "#0F6CBD",
  "login_background": null,
  "support_url": null
}
```

`includes/header.html` reads it and emits, on `<html>`:
`style="--f2-brand-primary: <accent>"` plus `data-f2-theme="<pref>"`.
Validate the hex server-side (`/^#[0-9a-f]{6}$/i`) before echoing. If `logo.header` is missing,
render `product_name` as text — never a broken image. Header logo box: max 120×24px, login logo
box: max 200×48px, both `object-fit: contain`.

## 3. Mail screen (direction 1a)

### 3.1 Layout shell

CSS grid, three panes plus rail. Widths from tokens; the two dividers are draggable and the sizes
persist to `rcmail.env` prefs (`fluent2_folders_w`, `fluent2_list_w`) via `rcmail.save_pref`.

```
grid-template-rows: var(--f2-header-h) 1fr;
grid-template-columns: var(--f2-rail-w) var(--f2-folders-w) var(--f2-list-w) 1fr;
```

Reading-pane position follows Roundcube's own layout pref (`rcmail.env.layout`):
`widescreen` = pane right (default), `desktop` = pane bottom, `list` = no pane (message opens as a
route, i.e. direction 1b's behaviour). The list toolbar exposes this as a "Reading pane"
split-button: Right / Bottom / Off.

### 3.2 App header — 48px, `--f2-brand-primary` background

Left: waffle/app-menu button (36×36, hover `rgba(255,255,255,.12)`), logo slot, product name (14/20
semibold, `--f2-on-brand`). Center: search field 520px max, 32px tall, `--f2-bg-1`, radius m.
Right: help, settings, avatar (28px circle, initials). All header icons `--f2-on-brand` at 20px.

Below 1024px the search collapses to an icon that expands over the header.

### 3.3 App rail — 48px, `--f2-bg-3`, right border `--f2-stroke-2`

Buttons 36×36, radius m, 20px icon. Selected = `--f2-brand-tint-selected` fill, brand icon, plus a
3px brand bar at the left edge of the rail. Order: Mail, Calendar, Contacts, Tasks (if plugin),
spacer, Filters shortcut. Render from `#taskmenu` so plugin-injected tasks appear automatically.
`aria-current="page"` on the active task. Tooltip = task name.

### 3.4 Folder pane — `--f2-bg-2`

- "New message" primary button, full width, 32px, brand, icon + label, `--f2-shadow-2`.
- Folder rows 32px, radius m, grid `20px 1fr auto`, gap 12px, padding 0 8px.
  Unread count right-aligned, 12/16 semibold, `--f2-fg-3` (brand when the row is selected).
- Icons by folder class: inbox, drafts, send, archive, report (junk), delete (trash), folder.
  Nested folders indent 16px per level; collapse chevron appears on hover/focus for parents.
- Selected: `--f2-brand-tint-selected` fill + 3px brand bar (inset 6px vertical) + semibold
  `--f2-brand-fg-strong`. Hover `--f2-bg-4`. Drag-over (message drop): 2px dashed brand outline.
- Labels/categories section under a 1px divider with a 12/16 semibold `--f2-fg-3` header; each row
  30px with a 10px rounded color swatch.
- Footer: quota label + 4px progress bar (brand fill; `--f2-danger` above 90%).

### 3.5 Message list

Toolbar (44px): select-all checkbox, mark unread/read, delete, archive, then right side: sort
split-button ("Date ▾"), density toggle, reading-pane toggle. Icon buttons 32×32, radius m, hover
`--f2-bg-3`. Overflow into a popover below 1200px (§5).

Focused / Other tabs (40px, only when enabled): active tab = brand text + `inset 0 -2px 0` brand
underline. Right side: "Filter" link opening the refine popover.

**Comfortable density** (default): grid `32px 1fr`, gap 10px, padding 8px 12px, divider
`--f2-stroke-3`. Line 1 sender (14/20) + time (12/16, right). Line 2 subject + thread count pill /
attachment / flag icons. Line 3 snippet (13/18 `--f2-fg-3`, truncated) and, if categorised, one
chip. Date group headers ("Today", "Yesterday", "Last week") 12/16 semibold `--f2-fg-3`,
sticky.

**Compact density**: 28px rows, columns
`28px 24px 200px 1fr 90px 70px` = checkbox · flag · From · Subject (with 8px category dot and
thread twisty) · Size · Received. Sortable column header row 32px on `--f2-bg-2`. This is direction
1c; it is a class on `#messagelist` (`.f2-density-compact`) plus a persisted pref
`fluent2_density`.

Row states (exactly as in the design file's component inventory):
rest `--f2-bg-1` · unread = semibold + 3px brand bar + `aria-label` prefix "Unread" ·
hover `--f2-bg-3` · selected `--f2-brand-tint-selected` + full-height 3px brand bar ·
multi-selected `--f2-brand-tint-strong` · focus = 2px inset focus ring.

**Hover quick actions**: right-aligned floating group (white, 1px `--f2-stroke-1`, radius l,
`--f2-shadow-4`, 2px padding) with Archive, Delete, Flag, Pin — replacing the timestamp. Shown on
`:hover`/`:focus-within` and on every row when a coarse pointer is detected only as swipe actions
(§6). Each is a real `<button>` with an accessible name; keyboard users reach them via the row's
action menu (Shift+F10 / context menu) as well.

**Threading**: use Roundcube's native `threads` mode. Restyle the `+/-` control as a chevron
twisty; child rows indent 20px; the parent row shows a count pill (11/16 semibold, `--f2-bg-4`,
radius circular).

### 3.6 Reading pane

Ribbon toolbar 44px: Reply (primary brand button), Reply all, Forward (secondary), divider, then
icon buttons Delete, Archive, Junk, Print, More (popover), and at the far right "Open in new
window". Content padding `--f2-read-pad`, text measure capped at `--f2-read-measure`.

Order: subject (20/26 semibold display) → category chips → sender block (40px avatar, name +
address, recipients line with "N more" disclosure, date right + flag/pin) → attachment strip
(rows: icon, name, type/size, download; plus "Download all (zip)" via zipdownload) → body →
divider → Reply / Reply all / Forward buttons.

HTML message bodies are untrusted: keep them inside Roundcube's iframe/sanitiser, inject only a
minimal typographic stylesheet (`--f2-font-body`, 15/24, `--f2-fg-1`, link color brand). Remote
content bar sits above the body: `--f2-warning-tint` background, 1px `--f2-warning` border, text +
"Load images" / "Always allow sender" buttons.

## 4. Other screens

### 4.1 Compose (`compose.html`)
Header row with title + expand/close. Field rows 8px/14px padding, 70px labels, `--f2-stroke-3`
dividers: From (select), To (recipient pills), Cc/Bcc links, Subject. Recipient pill: `--f2-bg-4`,
radius circular, 20px avatar + name + remove icon; invalid address gets `--f2-danger-tint` +
`--f2-danger` border and an `aria-invalid`. Editor toolbar on `--f2-bg-2` with 18px icons at 6px
padding. Footer 52px: Send (primary), Attach (secondary), emoji, schedule-send, more; right side
"Draft saved HH:MM" (12/16 `--f2-fg-3`) and Discard.
Override the TinyMCE skin with token-based CSS; do not ship a custom TinyMCE build.
Attachment upload: inline progress row with a 2px brand determinate bar; drag-over the body shows a
2px dashed brand outline + "Drop files to attach".

### 4.2 Login (`login.html`)
Centered card 376px wide, radius xl, `--f2-shadow-16`, padding 36/32, on a soft brand-tinted
gradient (`--f2-brand-tint-selected` → `--f2-bg-3`), overridable by `login_background`.
Logo slot, "Sign in" (20/26 semibold), subtitle with the mail domain, email + password fields,
password reveal toggle, "Keep me signed in" checkbox, full-width brand button, "Forgot password?"
link (only if `support_url` set) and a language select. Error banner above the fields:
`--f2-danger-tint` / `--f2-danger-stroke`, error icon, `role="alert"`, and it must receive focus.
Autofocus the first empty field; both fields need correct `autocomplete` attributes.

### 4.3 Search + refine
Search field expands to a full-width bar with **filter tokens**: `from: Rita`, `has: attachment` as
brand-tint chips with a remove affordance, free text after them. Typing `from:` offers an
autocomplete of contacts. "Filters" button opens the right-side **Refine panel** (260px,
`--f2-bg-2`): Scope radios (This folder / All folders / Subfolders / All accounts), Date select,
"Only show" checkboxes (Unread, With attachments, Flagged). Results list adds a folder chip per row
and a "N results in <scope>" summary line. Map tokens onto Roundcube's existing search params —
no new server code.

### 4.4 Settings
Three panes: nav (220px) · list (300px) · detail. Nav rows like folder rows. Detail forms use
`--f2-s-16` field gaps, 12/16 semibold `--f2-fg-3` section labels, sticky footer with
Save (primary) / Cancel.
**managesieve**: condition and action rows as `1fr 1fr 1fr auto` grids of Fluent selects/inputs with
a trailing delete icon button, "Add condition" text button with a plus icon; enable/disable per
filter is a Fluent switch (32×18, brand when on) in the list pane; the raw-Sieve editor gets a mono
theme (`--f2-font-mono`, `--f2-bg-2`, 13/20).
**Folder manager**: tree with drag handles, subscribe checkbox column, message-count and size
columns, and a right pane for create/rename/parent/purge.
Add a "Appearance" section to Preferences → Interface exposing: theme (Light / Dark / System / High
contrast), density (Comfortable / Compact), reading pane (Right / Bottom / Off), Focused inbox
(on/off). All four are Roundcube user prefs (`fluent2_theme`, `fluent2_density`, `layout`,
`fluent2_focused`) — no plugin needed if you register them from the skin's `ui.js` + a tiny
`fluent2_prefs` plugin for persistence.

### 4.5 Contacts
Panes: address books (200px) · contact list (300px) · detail. Rows 32px avatar + name/email.
Detail: 64px avatar, name (20/26), role/company, then a `90px 1fr` definition grid (Email, Phone,
Group chips, Notes), toolbar with Edit / Compose / Export / Delete. Generate initials avatars
client-side from the display name; pick the palette entry by a stable hash of the email.

### 4.6 Calendar
Restyle the calendar plugin (FullCalendar) with tokens: header toolbar matching §3.6, view switcher
as a segmented control (`--f2-brand-tint-selected` for the active segment), 52px hour rows,
`--f2-stroke-3` grid lines, day columns separated by `--f2-stroke-2`, today's column header in brand.
Events: radius m, `--f2-shadow-2`, 3px left border in the category color, tint background, 12/16
semibold title + 11/16 time. Event dialog uses the standard Fluent dialog (radius xl,
`--f2-shadow-28`).

## 5. Toolbar overflow rule

Toolbars measure available width on resize (ResizeObserver) and move trailing actions into a
"More" popover. Priority order — Mail list: select, delete, archive, junk, mark, move, sort,
density, pane. Reading pane: reply, reply-all, forward, delete, archive, junk, print, more.
Never drop the first three; always keep "More" visible when anything is hidden. Popover: radius l,
`--f2-shadow-8`, 4px padding, 13/20 items at 6px/10px, `--f2-bg-3` on hover, destructive item in
`--f2-danger`, 1px divider before it. Full ARIA menu semantics (`role="menu"`, arrow keys, Escape,
focus return).

## 6. Responsive

| Breakpoint | Layout |
|---|---|
| ≥ 1200px | rail + folders + list + reading pane |
| 768–1199px | folder pane collapses to the 48px rail (folders in a flyout); list + reading pane |
| < 768px | single pane; folders in a drawer; bottom tab bar (Mail/Calendar/Contacts/Settings); 64px list rows; 48px FAB compose bottom-right; reading pane forced to "Off" (message = route change) |

Below 768px: swipe left = archive, swipe right = flag (both with an undo toast); hover quick actions
are hidden; all hit targets ≥ 44px; the header keeps only menu, title, search.
Use container queries where a pane's own width matters (list densities), media queries for the shell.

## 7. `ui.js` responsibilities

Vanilla ES5-safe JS (no build step, no framework), namespaced `window.fluent2`:

1. Pane resize with persisted widths; keyboard-resizable (arrow keys on the divider,
   `role="separator"` + `aria-valuenow`).
2. Density toggle → class on `#messagelist` + `rcmail.save_pref('fluent2_density')`.
3. Theme switch → `data-f2-theme` on `<html>` + pref; honour `prefers-color-scheme` for "system".
4. Focused/Other tabs: two client-side scopes over the existing search API; remembers the last tab
   per folder in `sessionStorage`. Off by default when the pref is unset.
5. Hover quick actions: delegated listeners on `#messagelist tr.message`; Archive → archive plugin
   command, Delete → `rcmail.command('delete')`, Flag → `mark flagged`, Pin → a `$Pinned` IMAP
   keyword that sorts pinned rows to the top of the current folder.
6. Toolbar overflow (§5) via ResizeObserver.
7. Popover/dialog/toast primitives with focus trap + Escape + focus return.
8. Keyboard map (§9) using `rcmail.env` guards so it never fights Roundcube's own shortcuts.
9. Swipe actions below 768px (pointer events, 64px threshold, undo toast).
10. Initials avatars + stable palette hash.

Hook into Roundcube properly: `rcmail.addEventListener('init' | 'insertrow' | 'listupdate' |
'beforemove' | 'responsebefore')`. Never re-render the list yourself.

## 8. Categories / labels

Six presets mapped to IMAP keywords: `$Important`, `$Infra`, `$Finance`, `$QA`, `$Personal`,
`$Waiting` → the `--f2-cat-*` tokens. Displayed as chips (11/16 semibold, radius m, tint bg, fg
color) in the list and reading pane, as 8px dots in compact density, and as folder-pane filters.
Admin can rename them in `branding.json` (`categories: [{key, label, token}]`). Every category chip
carries its text label — a dot alone is never the only signal.

## 9. Accessibility gate

- Text contrast ≥ 4.5:1, UI strokes and icons ≥ 3:1, in all three themes. `#0F6CBD` on white is
  4.6:1 — never use brand for body text on tinted rows; use `--f2-brand-fg-strong` there.
- Focus: 2px `--f2-fg-1` outline + 1px inner ring (mixin `f2-focus-ring`), 2px offset, on every
  interactive element. `:focus-visible` only; never `outline: none` without a replacement.
- Unread is weight + bar + `aria-label`, not color. Flags and categories carry text.
- Landmarks: rail `<nav aria-label="Apps">`, folders `<nav aria-label="Folders">`,
  list `role="grid"` with `role="row"`/`role="gridcell"` and roving tabindex (single tab stop),
  reading pane `<main role="region" aria-live="polite" aria-label="Message">`.
- Keyboard: `j`/`k` move, `Enter` open, `x` select, `e` archive, `#` delete, `u` mark unread,
  `f` flag, `r`/`a` reply/reply-all, `c` compose, `/` search, `F6` cycles panes,
  `Shift+F10` row menu, `Escape` closes overlays. Document them in a `?` dialog.
- Screen-reader announcements for row selection changes, new mail, and toast content
  (`aria-live="polite"`; errors `assertive`).
- Respect `prefers-reduced-motion` and `forced-colors: active` (both already wired in
  `_tokens.scss`).
- Zoom to 200% and 320px width without loss of function; no horizontal scroll.

## 10. Icons

Use **Fluent UI System Icons** (MIT, github.com/microsoft/fluentui-system-icons), self-hosted as a
single SVG sprite in `images/icons/fluent-sprite.svg`, referenced with
`<svg class="f2-icon"><use href="…#ic_fluent_mail_20_regular"></use></svg>`. Regular 20 for rest,
Filled 20 for selected/active states. `currentColor` fill, `aria-hidden="true"` unless the icon is
the only label. Subset to the icons actually used (~60). Do **not** use an icon webfont, do not
inline the whole set, and do not ship Microsoft product logos or illustrations.
(The design mockup uses a stand-in icon font — match the shapes, not that font.)

11. Calendar and remaining plugins.
12. Dark + high contrast + forced-colors.
13. Responsive/mobile pass incl. swipe + FAB + bottom tabs.

## 13. Definition of done

- Skin installs by copying `skins/fluent2/` and setting `$config['skin'] = 'fluent2';` — nothing else.
- All 4 tasks (mail, addressbook, settings, calendar) render with no console errors and no
  unstyled core markup, in Chrome, Firefox and Safari.
- `grep -nE '#[0-9a-fA-F]{6}' styles/*.scss` matches only `_tokens.scss`.
- Light, dark, high-contrast and forced-colors all pass the contrast rules in §9.
- Keyboard-only walkthrough of read → reply → send → archive → search → settings works.
- 360px, 768px, 1280px and 2560px screenshots match the design file's layouts.
- Changing `branding.json` accent + logo restyles the whole UI with no other edit.
- With JS disabled, mail still lists, opens, and sends.

## 14. Deliverables

Working skin folder, committed `styles.css`, a `README.md` (install, branding, dev/build,
prefs added, plugin compatibility notes), and a short `CHANGELOG.md`.
Ask before adding any dependency beyond Sass and the Fluent icon SVGs.
